# Meeting editing: linked-record explanations and direct task editing

- An Action Item card in both overview and detail displays an Edit pencil when the signed-in user originally assigned/created the action item and the task is not cancelled. Opening the editor does not first open Task Details. The existing meeting Action Item dialog and backend owner guard remain authoritative.
- The meeting edit dependency read endpoint is available to the organizer of any scheduled Meeting; the previous historical URL remains valid for older clients. Historical and regular scheduled meeting Agenda editors use the same dependency display. Dependency query cache entries are invalidated when meeting Action Items and Decisions are updated.
- Historical meeting dependencies are read from the backend. The response includes specific participant dependency categories and agenda linked task/decision counts. Locked participant/agenda actions stay visible and provide localized explanations on click and keyboard activation; they are not silently disabled.
- The shared client `meeting-edit-restrictions.ts` converts backend reason codes into localized Arabic/English messages. It is also used when the backend detects a conflict at save time (including concurrent changes). Backend transaction guards and database foreign keys remain the real protection, never the UI alone.
- The existing agenda workspace uses the same protected-topic UI; update failures use the same backend error formatter. Meeting Action Item edit/create failures also display their backend error codes where translations exist, with a fallback.
- No new migration required for this incremental UI/backend-query patch. **The prior historical-editing migration 058 remains required** if the previous feature has not been deployed. Do not run SQL migrations without explicit approval.
